# Approved GR Store and Supabase phase

## Current architecture

The earlier Firebase-backend amendment was incorrect and is superseded. Firebase is for Google/email authentication only; Supabase PostgreSQL, Storage and Edge Functions handle store data and protected operations. The definitive correction is in `2026-11-02-supabase-correction-design.md`; current activation instructions are in `docs/runbooks/supabase-setup.md`. The original requirements below are retained for design context; identity-specific Supabase Auth references are superseded by Firebase Auth.

The owner approved the GR Store browser concept on 2 November 2026 and requested implementation with the backend. This supersedes the original dark/lime NUTRIVAULT direction.

## Experience

Use GR Nutritions branding, cream #F7F7F2 surfaces, white product cards, forest #214A33, coral #EF4B32, dark #101513 campaign hero, Barlow Condensed headings and DM Sans body. Preserve the approved campaign photograph in application assets. Use Lucide icons, a search-led header, goal tiles, brand rail, product collections, visible coach launcher, and mobile icon tabs. Real catalog photos come from admin media uploads; generated imagery remains explicitly concept imagery, never mislabeled as another brand's pack.

Browsing remains public. Checkout requires a restored authenticated session and a saved Indian delivery address belonging to the customer. Customers can create, edit, delete, and choose a default among multiple addresses. Login supports email/password registration and recovery plus Google OAuth through Supabase with browser/native redirect handling. Unconfigured services show accurate setup errors, never simulated authenticated users or successful orders.

## Backend

Supabase Auth, Postgres, Storage and Edge Functions. Catalog tables store validated product payloads plus indexed relational brand, category, status and variant stock/price columns. Customer addresses and orders use owner-only RLS. Admin membership is server-controlled, cannot be set in user metadata, and guards catalog writes, image uploads, inventory and order transitions. Draft media is private and delivered by signed URLs. Public products expose only active records. One transactional RPC saves a complete product and variants, enforcing unique SKUs, price/MRP and integer stock. Inventory-aware checkout RPC calculates totals and snapshots address/items with an idempotency key; payments are not captured until Razorpay is configured. Credentials never ship to the client except the public URL and publishable key.

Admin supplies overview, catalog list, product creation/editing, media upload, variants, draft/publish, inventory and orders. Uploads validate image type/size; credentials and permission errors are readable. No cloud account or billing setup is assumed complete.

## Coach

Implement an actual interactive guided recommendation flow using catalog, goal, budget, dietary preferences and stimulant preferences. Safe deterministic matching works without an external AI account. Server Edge Function adds optional conversational AI only with a server-side key; returned products must still pass deterministic catalog eligibility. Never claim rule-based results are generated by an LLM. Avoid medical diagnosis and stop rankings for minors, pregnancy, medication/medical-condition concerns. Do not infer product safety from missing data; publishable eligibility fields must be reviewed.

## Scope and approach

Retain Expo Router and the tested cart/repository foundation. Replace visual components and wire a configurable Supabase adapter; use the sample catalog when no backend settings exist, labeled in the shopping UI. Real third-party brands are supported as data, but do not invent live inventory, reviews or commercial affiliation. Local SQL tests must prove owner isolation, denied self-promotion, draft visibility, server totals, stock validation, SKU conflicts and idempotency. Live Google OAuth and cloud policies require a configured owner project before launch verification.

Alternatives considered: wholesale rewrite loses working domain tests; UI-only redesign leaves customer requirements missing; coordinated redesign plus backend preserves useful contracts and delivers the approved flow. The owner selected the coordinated approach.
